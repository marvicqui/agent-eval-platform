# Metrics, thresholds and evidence

Threshold source: [`evals/thresholds.yaml`](../evals/thresholds.yaml).
Implementation reviewed 2026-10-10. Model measurements below are historical
2026-08-04 values from [`evals/baseline.json`](../evals/baseline.json).

## Configured quality gates

| Metric | Meaning | Floor | Allowed drop from baseline |
|---|---|---:|---:|
| `faithfulness` | Support for answer claims in retrieved context | 0.85 | 0.05 |
| `answer_relevancy` | Alignment between answer and question, using the RAGAS evaluator | 0.70 | 0.05 |
| `context_precision` | Relevance of retrieved context against the reference | 0.70 | 0.05 |
| `context_recall` | Coverage of what the reference answer needs | 0.70 | 0.05 |
| `judge_overall` | Rubric weighted score normalized from 1–5 to 0–1 | 0.70 | 0.05 |

Judge weights are technical accuracy 0.4, completeness 0.3 and actionability 0.3.
The historical answer-relevancy floor was lowered from 0.80 to 0.70 after the
first run's 0.7572 mean. That was a threshold adjustment, **not human calibration**.
The repository does not preserve a repeated-run distribution that establishes
0.05 as statistically justified across models or datasets. Treat these as
versioned engineering choices to re-examine with new evidence.

## Bias monitors

- **Position flips:** fraction of valid both-order comparisons with inconsistent
  verdicts. The stored **0.2667 exceeds the target <0.10**. A flipped pairwise
  result becomes a tie, but `judge_overall` is computed separately and unchanged.
  Same-model judging and near-ties are possible explanations, not demonstrated
  causes of this measured rate.
- **Verbosity correlation:** Pearson correlation between answer length and
  rubric score. Historical 0.2686 falls within the target |r|<0.30, but one small
  sample does not establish that verbosity bias is absent or eliminated.
- **Self-preference:** the guard checks deployment-name equality. Distinct
  aliases can still route to the same model. The historical evaluation workflow set the explicit
  same-deployment override.

Both derived metrics are printed by `aep report`; neither is passed into
`evaluate_gate`. Switching judge deployments alone does not turn them into gates.
Human Spearman/kappa calibration remains pending.

## Trajectory and missing-data behavior

`forbidden_tool_calls` has a hard-coded veto if its aggregate maximum exceeds
zero. Precision/recall, loop detection, ordering and step count are emitted when
a case declares trajectory expectations. They have no configured YAML thresholds.
`max_steps_exceeded` is computed by the pure checker but is not emitted by the
adapter. The historical evaluation dataset, `rag_qa`, does not declare trajectories.

RAGAS failures emit `None` values; valid values determine means. A completely
missing thresholded metric fails, while partial failures need not fail.
Malformed rubric output produces `judge_error=1` separately, and invalid pairwise
output omits that case's flip metric. No complete evaluator-error-rate gate is
implemented. These omissions can affect coverage and interpretation of averages.

## Cost boundary

`total_cost_usd` sums the runner's instrumented SUT costs. Judge/RAGAS requests
are outside this collection. Unknown prices are flagged on spans and counted
per case, but their dollars are absent from the numeric total. The price table
is a historical configuration, not a current billing quote. A log-ingestion cap
is not a complete Azure spending cap. See [limitations](limitations.md).
